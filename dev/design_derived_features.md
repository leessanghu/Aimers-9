# mc8 신호가 약할 경우의 대안: 파생피처 추가

## 왜 파생피처가 다른 레버인가

지금까지의 헤드들은 전부 **보조타겟(multi-task)** 방식이다:
- 라벨을 as-of 차분으로 복원 -> `Y = [y, aux...]` 로 학습 -> 추론시 head0만 사용
- 이건 모델의 **표현**을 바꾸는 것이지 **입력 정보**를 늘리는 게 아니다

파생피처는 다른 축이다:
- 학습데이터로 만든 **룩업테이블**을 test에서 `pitcher_id` 등으로 조회 (Rule4 안전)
- 모델이 실제로 **새 입력**을 받는다

## 중요한 제약 (이미 실패한 사례)

`probe_pitchtype_channel.py`에서 시도한 "투수 구종의존도(spread)" 피처는 실패했다:
- fold A rho +0.00267, fold C +0.00005 (재현 안 됨)
- 원인: (투수 x 구종)으로 쪼개면 셀당 표본이 급감 -> 축소가 강하게 걸려 신호가 죽음

`probe_pitchtype_derived_feature.py`의 `expected_success_by_mix`도 실패:
- fold A -0.00663 / fold B -0.03073 / fold C +0.00975 -> 3fold 중 2fold 음수, 부호 불일치
- 원인: (투수 x 구종) 성공률 테이블이 리그 드리프트에 취약 (train->valid 드리프트가
  클수록 부호가 뒤집힘. fold C만 드리프트 -0.014로 작아서 양수)

**교훈: 투수 단위로 잘게 쪼개는 룩업은 표본부족 + 드리프트로 죽는다.**

## 그래서 살아남을 가능성이 있는 설계

### (a) 전역 조건부 테이블 (투수로 안 쪼갬)
mc6가 발견한 숨은 라벨들을 **전역 조건부 확률**로 만든다. 투수별이 아니라
카운트/상황별이라 셀당 표본이 수만~수십만이라 축소가 거의 안 걸린다.

```
f1 = P(succ_ball | count_state)      # 이 카운트에서 '존밖 요구 성공'이 나올 확률
f2 = P(succ_strk | count_state)
f3 = P(wild_strk | count_state)      # mc8이 새로 분리하는 클래스
f4 = P(succ_ball | count_state, 구종)
```
train 전체에서 groupby 평균. test에서는 자기 행의 `balls/strikes`만 참조 -> Rule4 안전.
셀 수가 12(카운트) 또는 36(카운트x구종)이라 표본 충분.

### (b) 투수별이되 축소를 아주 강하게
꼭 투수별로 가야 한다면 K를 크게(200~500) 잡아 전역평균으로 강하게 당긴다.
`build_lgbm_count02_feature.py`에서 K=30이 너무 약해 실패했던 전례가 있으므로
K 스윕(200/500/1000)을 반드시 포함.

### (c) 드리프트 내성 설계
절대 성공률 대신 **전역 대비 편차**로 저장하면 리그 레벨 이동에 강해진다.
```
f = rate(pitcher, cond) - global_rate(cond)     # 레벨이 아니라 편차
```
fold C만 양수였던 게 드리프트 때문이었으므로 이 형태가 핵심.

## 검증 절차 (기존과 동일)
1. fold A/C/B 3폴드에서 rho 부호 일치 확인 (2/3 이상 같은 부호여야 함)
2. mc6/strk/pitchtype과의 d벡터 상관으로 독립성 확인
3. 통과하면 프로덕션 학습 -> 프로브 제출로 실제 A 측정

**단, 로컬 rho의 크기는 반정보이므로 기각 근거로 쓰지 않는다
([[probe-first-methodology]]). 부호 일치와 독립성만 스크리닝에 쓴다.**
