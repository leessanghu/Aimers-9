## 검증기준 재정립 (fold A/B/C 우선순위)

실측검증 3건(v42/v43b/v46)의 로컬-실제 비율 분석:
```
              foldA   foldC   foldB   실제LB
v42           7.01    12.17   33.45   13.57   (A/실제=0.52 C/실제=0.90 B/실제=2.46)
v43b          1.64    9.32    9.60    0.95    (A/실제=1.73 C/실제=9.81 B/실제=10.11)
v46           1.29    14.93   15.01   1.11    (A/실제=1.16 C/실제=13.45 B/실제=13.52)
```
- min(A,C) 규칙은 3건 모두 fold A값으로 귀결됨(fold A가 항상 더 작았음) — 즉
  "클린폴드 최소"는 사실상 암묵적으로 "fold A 우선"이었음.
- fold A/실제 비율은 0.52~1.73(같은 자릿수, 방향 항상 일치) — 신뢰 가능.
- fold C/실제 비율은 0.90~13.45배(들쭉날쭉, 종종 대폭 과장) — 학습표본 최소
  (2019-2021, 3시즌)라 노이즈가 큼. Bates-Granger 분석에서도 fold C 최적해가
  fold A와 다르게 나옴.
- fold B/실제 비율은 항상 과장(2.46~13.52배), Bates-Granger 최적해가 multires
  100% 몰빵이라는 퇴화해 — 대표성 낮음 재확인.

**갱신된 판정기준**: fold A(2024, train≤2023)를 주검증으로 방향+크기 신뢰.
fold B(2023, train≤2022)는 "크게 망가지지 않는지"만 참고, 크기는 무시.
fold C(2022, train≤2021)는 시드/구간 안정성 점검용으로 강등, 크기는 무시.

시간순ES, regressor전환)은 "기존신호 재활용" 계열, 실패 2건(레벨이동, 폼나우

특히 민감한데 fold A는 프로덕션 대비 1개 시즌(약 17%) 적음.

**갱신 지침**: target reformation류(공유트리 auxiliary head)는 fold A 음성만으로
기각하지 말고 실측 확인을 우선 고려. 가중치/전처리류는 기존 fold A 우선 지침 유지.

가능한 원인: iteration을 정한 8% 홀드아웃과 100% 데이터의 최적 반복수가 다를 수 있고,
특히 가장 최근 8%(2024 후반)를 포함시켜 재학습하면 그 구간에 과적합되어 실제 2025
(테스트) 방향의 일반화가 오히려 나빠질 수 있음 -> "최근 데이터를 더 본다"가 항상
이득은 아님을 시사. 다음 실험(multires/midaxis/ordinal refit-closure 확장)은 이
반증을 감안해 보류.

전체데이터로 재학습하면, 그 최근 구간의 시즌 특유 변동(불펜 개편, 부상 복귀, 로스터
막바지 변화 등)에 트리가 과적합되어 오히려 2025로의 일반화가 나빠질 수 있음.
"최근 데이터를 더 반영한다"는 직관과 반대로, 이 문제에서는 검증 없이 최근 데이터를
전부 학습에 밀어넣는 것 자체가 손해일 가능성.

**조치: v54(ordinal refit)/v55(multires refit)도 같은 계열이라 좋은 결과 기대하기 어려움.
학습은 완료시키되(이미 돌고 있음), 실측 제출은 사용자 판단에 맡기고 먼저 이 경고부터 전달.**
남은 두 실험도 마저 실측해서 3/3, 4/4 패턴인지 최종 확인하면 "refit-closure는 이 문제에서
전반적으로 해롭다"를 이 세션의 확정 규칙으로 남길 수 있음(현재는 n=2).

**refit-closure(ES로 iter확정 -> 100% 데이터 재학습) = 6/6 실측 음수, 평균 약 -4.**
반면 로컬은 전부 강한 양수(cats fold A +6.75 / fold C +24.50). 로컬↔실측 부호가

v45에서 이미 같은 교훈이 나왔으나 "hurdle 특유 문제"로 국소화해버려 재발했음.

### 왜 v50이 최고인가
v50 이후 모든 버전이 "학습 프로토콜 변경"(refit) 뿐이었고 전부 실패. v50은
"ES모델 보존 + 새 정보축(aux head) 추가"라는 두 조건을 만족하는 마지막 버전.
점수를 올린 개입은 전부 **새 정보 추가**(multires/ordinal/midaxis/가중치최적화)였고,
**학습절차 개선**은 단 한 번도 성공한 적이 없다(0/6).

### 반증된 가설들 (기록 필수)
1. "월 분포 불일치가 refit 실패 원인" -> **반증**. refit 이득은 오히려 시즌초에서
   더 큼(3-5월 +9.75, 3-7월 +9.99, 8-10월 -0.72).
2. "다양성 손실" -> **반증**. refit이 hgb/hurdle/ordinal과의 상관은 +0.010 올리고
   multires/midaxis와는 -0.010 내림(혼재, 일관성 없음).
3. "레벨 이동" -> **반증**. cats refit의 레벨변화 -0.00195(성분), 블렌드 기여
   -0.000195 -> 예상 영향 +0.36점뿐. 관측된 -2.48을 설명 못함.
-> **refit 실패의 메커니즘은 여전히 미해결.** 단 실측 6/6이므로 규칙으로는 확정.

### 정정 (내가 앞서 과잉주장한 것)
"과거 피처 스크리닝이 시드노이즈에 다 묻혔을 것" -> **틀림.**
feature_factory stage1/2는 `partial_gain`(잔차 편상관) = 모델학습 없는 결정론적
추정량이라 시드노이즈가 0이고 sigma=1/sqrt(n)~4.0점 기준을 씀. 신뢰 가능.

### [정정] 단일 프로브는 b_S(그 집합의 모델 편향)에 취약
share = drop / (K x (2*d*b_S + d^2)) 인데 b_S를 모른다:
```
b_S=+0.0100 -> share  6.5%
b_S=+0.0025 -> share 10.4%   (v48 전역편향 가정, 앞서 보고한 값)

### [확립] ±델타 쌍 프로브 — b_S 완전 소거
```
drop(+d) = K x share x ( 2*d*b_S + d^2)
drop(-d) = K x share x (-2*d*b_S + d^2)
합: drop(+)+drop(-) = K x share x 2*d^2      <- b_S 소거, share 직접 확정
차: drop(+)-drop(-) = K x share x 4*d*b_S    <- b_S도 역산
```
축당 제출 2회로 **가정 없는 정확한 share + 그 집합의 모델 편향**을 동시에 얻는다.

## 곱셈분해 확장안 검증 — 제안 A/G는 기존 hurdle과 동일, 3단계는 성립 안 함

### 검증1: dangerous = middle or reverse == 기존 core_fail (동일)
```
dangerous 발생률 34.45%  == core_fail 발생률 34.45%   <- 정의가 같음
P(success|dangerous)=0.0000  P(success|not dangerous)=0.7990
2단계 분해: 0.6555 x 0.7990 = 0.5237 == 실제 성공률 0.5237  <- 완전분해
```
**제안 A(dangerous_hurdle)와 G의 1~2단계는 v32 hurdle(실측 +15)과 수학적으로 동일.**
이미 프로덕션에 w=0.32로 들어가 있음 -> 새 정보 없음.

### 검증2: 3단계 캐스케이드(not dang -> not ball -> success)는 분해가 안 됨
```
P(not dang)=0.6555 x P(not ball|not dang)=0.5952 x P(succ|clean)=0.9405 = 0.3669

```

즉 ball은 success의 상위 계층이 아니라 **부분적으로 겹치는 축**.
-> 제안 G(sequential_hurdle 3단)는 계층 전제가 깨져서 구성 불가.

### 실측으로 역산한 test 파라미터 (프로덕션 rhat 실측 E[rhat^2]=7.68e-4 사용)

-1.8639점 -> E[rhat*(p-y)] = -1.51e-5
=> test 최적 alpha = 0.0197   (쓴 값 0.10은 5.1배 과보정)
=> 최적 alpha에서의 기대이득 = +0.119점  (사실상 무가치)
=> test에서 v66의 Cov/Var ~ 1.002  (거의 완벽 캘리브레이션)
```
**결론: 샤프닝/캘리브레이션 계열은 test에서 완전 소진.** 재제출 가치 없음(+0.12점).

- batter event trait은 절편 대비 0 이하로 기각.

따라서 다음 실험은 과거표 추가가 아니라 CatBoost 4-class PA-event aux head여야 한다.

### count-conditioned multiclass decoder

현재 multiclass는 `P(class|x) @ E[y|class]`로 변환하면서 공개된 현재 count를 마지막에 버린다.
`E[y|class,count]`로 디코딩하면 5-class 로컬 예측이 569.09→721.97(+152.88)로 상승했다.
오라클상 15-class에 count가 주는 resolution 증분은 +0.000840이다.

그러나 5-class count decoder와 MLP를 혼합해 단독 775까지 올려도 v66과의 오차상관이 함께
증가해 손익분기 margin은 -0.000075 부근에 고정, blend 가중치 0이었다. 예측값 상관보다
오차상관 조건이 중요하다는 재확인이다. 15-class에도 count decoder는 적용 가치가 있지만,
그 자체가 새 직교축은 아니다.

### 1) InGame 미사용 head1 signed correction
